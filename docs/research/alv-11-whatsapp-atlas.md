## Achado e recomendação

Decisão do usuário: envio todo mês nos dias **15 e 28, às 07:00**, no fuso `America/Fortaleza`. Esta decisão substitui as datas anteriores. O destinatário foi informado e registrado no Linear; configurar seu valor no servidor, fora do código versionado. As duas datas existem em todos os meses, incluindo fevereiro.

Para ALV-12, a proposta é um botão manual na Alva que chama uma única operação de despacho Rails. Essa operação monta uma fotografia somente leitura dos itens pendentes em `ListItem.on_list.pending`, agrupados por categoria, e envia o texto ao Hermes. Não muda itens, não finaliza `ShoppingTrip` e não inclui comprados ou arquivados. ALV-13 agenda o envio da mesma lista usando essa operação.

O Hermes documenta uma ponte adequada: webhook `deliver_only`, com `deliver: whatsapp`, transforma o campo `prompt` do POST na mensagem literal, não executa agente/LLM e retorna `200` após entrega ou `502` em falha do adaptador. A assinatura HMAC V2 usa corpo e timestamp; sua validação rejeita relógio com diferença acima de cinco minutos. Configure o destino fixo no Hermes, nunca no corpo do pedido. Essa é uma interface documentada no upstream; só deve ser escolhida para Atlas depois de confirmar a versão, o tipo de canal e que essa versão entrega WhatsApp por essa rota. [Webhook Hermes, commit fixado](https://github.com/NousResearch/hermes-agent/blob/098365431981841fa66497875c606a459a557830/website/docs/user-guide/messaging/webhooks.md#direct-delivery-mode)

Fluxo proposto: botão com proteção CSRF → `ListDelivery.dispatch!(trigger: :manual)` → fotografia/renderização → POST assinado para a rota Hermes fixa → resultado mostrado na Alva. Hermes é um serviço de saída; a página não recebe segredo. A ausência de login na Alva continua sendo uma decisão do produto: o segredo de serviço fica apenas no servidor. Não há necessidade de criar uma API para ler a lista caso a operação Rails já obtenha a fotografia e a envie. Não passe argumentos de shell nem permita escolher destino pelo navegador.

## Contrato ALV-12/13 proposto

- Um único serviço Rails, por exemplo `ListDelivery.dispatch!(trigger:, period_key: nil)`, gera a fotografia atual e renderiza texto simples em português com título, data/hora Fortaleza e títulos de categoria. Não usa Hermes para interpretar conteúdo.
- Botão manual executa o serviço imediatamente. A UI mostra **Enviado** só após confirmação `200/status=delivered`; mostra **Lista vazia** sem enviar ou envia uma mensagem vazia conforme decisão do produto; mostra **Falha** para rejeições definitivas e **Resultado desconhecido** quando há timeout após o POST. `202/status=accepted` é apenas enfileirado e não serve como confirmação de entrega.
- ALV-13 chama esse mesmo serviço; a chave estável é household + período, por exemplo `household_id + 2026-03-15`, `household_id + 2026-03-28`. Não deduplicar só pelo hash do conteúdo: a mesma lista deve poder ser enviada em períodos diferentes. Criar unicidade persistente por `(household_id, period_key)` para impedir concorrência/reenvio do mesmo período. Despacho manual não consome a chave agendada.
- Janela de atraso **proposta: 48 horas** após o horário previsto. Ao voltar online dentro da janela, examinar períodos vencidos ainda válidos e entregar uma vez por chave; depois da janela, marcá-los expirados e expor o estado no app/log, sem envio tardio. Confirmar se múltiplos períodos ainda válidos podem produzir mensagens consecutivas. Systemd pode iniciar apenas uma ativação atrasada; o serviço precisa calcular os períodos pendentes por calendário para cumprir essa política.
- Registrar status e horários: pendente, enviando, entregue, falha, resultado desconhecido ou expirado; registrar chave, hash, tentativa e erro sanitizado, sem conteúdo integral ou segredos. Falhas temporárias podem ser repetidas com backoff limitado; `401/403` indicam configuração/autorização e não devem entrar em repetição cega.
- Hermes documenta `200/status=duplicate` para o mesmo ID de entrega durante uma hora. Esse retorno impede novo envio, mas não prova o resultado do primeiro POST se houve perda de resposta. Marcar esse caso como **desconhecido**, não como entregue. Timeout após aceite também é ambíguo: não há promessa de “exatamente uma vez”; apresentar retry manual explícito ou regra de retry escolhida. A deduplicação durável da Alva por período continua necessária. [Webhook Hermes: respostas e idempotência](https://github.com/NousResearch/hermes-agent/blob/098365431981841fa66497875c606a459a557830/website/docs/user-guide/messaging/webhooks.md#response-codes)
- Tratar listas longas antes do envio: limite e divisão variam por adaptador. Preservar categorias/itens ao dividir, numerar partes e registrar entrega parcial; retries podem repetir partes já enviadas. Confirmar limite do canal efetivamente instalado antes de implementar a divisão.
- Um erro ao obter a lista nunca pode ser convertido em lista vazia.

## Fatos verificados no repositório e no upstream

- Alva é Rails; `ListItem.on_list` exclui itens arquivados, e `pending` define o conjunto para envio. O fuso de Rails está hoje configurado como `America/Sao_Paulo`; isso não autoriza herdar esse valor para agenda. Solid Queue 1.7.0 está no lockfile, e o deploy carrega o plugin em Puma. [ListItem](../../app/models/list_item.rb), [configuração da aplicação](../../config/application.rb), [deploy](../../config/deploy.yml), [Gemfile.lock](../../Gemfile.lock)
- Hermes upstream documenta `deliver_only`, canal de destino `whatsapp`, destino opcional configurável no servidor e CLI `hermes webhook subscribe`. O endpoint retorna `202` para `cron_job`; portanto não é confirmação síncrona para o botão. Preferir `deliver_only` para entrega literal sem agente. [Webhooks Hermes, commit fixado](https://github.com/NousResearch/hermes-agent/blob/098365431981841fa66497875c606a459a557830/website/docs/user-guide/messaging/webhooks.md)
- Hermes documenta Baileys como ponte vinculada a dispositivo e WhatsApp Cloud como integração separada. `hermes send` não deve ser presumido compatível com o Baileys. Cloud traz dependências de conta Meta, credenciais e janela de mensagens; custos de Meta não foram calculados. [WhatsApp Hermes, commit fixado](https://github.com/NousResearch/hermes-agent/blob/098365431981841fa66497875c606a459a557830/website/docs/user-guide/messaging/whatsapp.md), [WhatsApp Cloud Hermes, commit fixado](https://github.com/NousResearch/hermes-agent/blob/098365431981841fa66497875c606a459a557830/website/docs/user-guide/messaging/whatsapp-cloud.md)
- A rota direta Hermes evita custo de inferência LLM. Continuam os custos e riscos do canal escolhido: sessão/dispositivo Baileys ou configuração/possíveis tarifas e políticas do Cloud. Nenhum desses detalhes foi confirmado no Atlas.
